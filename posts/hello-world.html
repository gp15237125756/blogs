开博第一篇：这个博客写什么

在官方文档、AI 助手和问答社区都很发达的 2026 年，为什么还要自己搭一个静态博客？这篇说说我的理由，以及这里准备写哪些内容。

  • #随笔
  • #博客

为什么还要写博客#

工作几年之后会发现，真正让人反复踩坑的往往不是"没用过某个技术"，而是当时想明白了、过几个月又忘了的那些判断。

排查一次线上告警时，你可能是这样得出结论的：

这个接口的 P99 高，不是慢 SQL，是连接池等待。因为 DB 侧的活跃连接数一直没打满，而应用侧的获取连接耗时占了请求时间的 80%。

结论很清晰，但三个月后遇到同类问题，你可能又要从"Druid 监控在哪看"开始重新推一遍。博客对我最大的价值，就是把这些推理链条固化下来。

官方文档回答"这个 API 是什么"，而我想记录的是"在什么约束下我选择了它"。

这里准备写什么#

大致会覆盖这几条线，优先级从高到低：

  1. Java 与 JVM：GC 日志、内存模型、并发工具、性能排查
  2. 分布式系统：消息队列、分布式事务、一致性、幂等设计
  3. 数据库：MySQL 索引与执行计划、分库分表、缓存一致性
  4. 工程实践：可观测性、发布与回滚、故障复盘
  5. 随笔：读书笔记、工具与工作方法

写作原则只有一条：能复现的才写。涉及具体参数的地方，尽量给出可执行的命令或代码，而不是"建议调大一些"。

这个站点怎么搭的#

站点本身也是我的一次练习：不使用任何框架和 npm 依赖，用 Node.js 写了个约 600 行的静态生成器。

# 写一篇 Markdown，然后构建
node scripts/new-post.mjs "标题"
node scripts/build.mjs

目录结构很直白：

content/posts/    Markdown 原文
templates/        HTML 模板
scripts/build.mjs 生成器
assets/           CSS / JS / 图片

构建产物是纯静态文件，直接推送到 Gitee 就能用 Pages 托管。没有 Node 环境也能维护，因为生成的 HTML 本身就可以直接改。

关于订阅与反馈#

如果你用 RSS 阅读器，可以订阅 feed.xml；如果发现问题，欢迎在 Gitee 仓库提 Issue。

最后，借用一句常被引用的话作为开篇：

写下来，是为了让未来的自己少走一遍弯路。

希望这里的每一篇，都能在某个时刻帮你省下半小时。
